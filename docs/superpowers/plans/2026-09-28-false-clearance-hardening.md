# 오인 승인 방지 검증 강화 실행 계획

> 사용자 승인: 2026-09-28 "오인 승인 방지 검증 강화 부터 진행".
> 기존 제안(위험 입력 점검 → 실패 테스트 → 최소 수정 → 개발 검증 기록)의 실행이다.
> 실행: 현재 격리 worktree에서 인라인 TDD. 사람 검토 재개나 새 기능 확장이 아니다.

**Goal:** 복합 주장 일부 일치, 부정문, 원료 귀속 혼동으로 문장 전체가 확인되는 재현 오류를 차단한다.

**Architecture:** 기존 추출 → 결정론적 판정 → 영수증 흐름을 유지한다. 광범위한 키워드 추출은
후보 생성에만 사용하고, 긍정 판정 직전에는 문장 전체가 단일 지원 표현인지 대조한다.
지원하지 않는 수식·다중 효과·주체는 자동으로 쪼개거나 추정하지 않고 검증 불가로 보류한다.
공식 기능성의 혼합 헤더와 부정 문구는 긍정 근거로 쓰지 않는다.

**Tech Stack:** 기존 Python, pytest, FastAPI TestClient만 사용. 패키지 추가 없음.

## 경계

- AI가 만든 합성 회귀 사례이며 사람 정답·동결 평가·서비스 정확도가 아니다.
- 제품/주장 확인 게이트와 원문 span, source_id, 조회 시각을 보존한다.
- A 라벨, C003 스냅샷, 원료 규칙/manifest, pilot-002 답변지, 확장 B/C를 변경하지 않는다.
- 불명확한 문장을 보류하는 비용은 허용하되 기존 단일 긍정 대조군도 검증한다.
- 의미가 바뀐 추출/공식 파서/판정 버전을 올려 영수증에서 구분한다.
- 실제 광고 전체, 임상 효능, 법적 적합성, 모든 한국어 부정/수식의 완전 처리는 주장하지 않는다.
