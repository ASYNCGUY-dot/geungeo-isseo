# 화장품 확장 계획

- 사용자 결정(2026-10-07): "여기서 화장품까지 판별 대상으로 넣자", "발표 기한 고려하지 않고 작업해도 된다".
- 브랜치: `cosmetics-data-gate`. 발표용 MVP(`phase-0-c003-data-gate`의 `71f3b30`)는 건드리지 않는다.
- 조사 기록: [화장품 공식 데이터소스 조사](../../evidence/COSMETICS_DATA_SOURCES_2026-10-07.md).

## 목표

화장품 광고의 주장을 공식 데이터와 대조해, 확인된 범위와 확인할 수 없는 범위를 근거영수증으로 보여 준다.
건강기능식품과 같은 원칙을 지킨다. 최우선 지표는 오인 승인율이고, 근거가 부족하면 `검증 불가`로 멈춘다.

## 지키는 제약

- 데이터 실측(0단계) 전에는 화장품 판정 규칙, 화면, 평가세트를 만들지 않는다.
- `확인됨`은 사용자가 확정한 제품의 공식 효능효과와 명시적 규칙이 일치할 때만 낸다.
- 일반 화장품(기능성 보고·심사가 없는 제품)에는 `확인됨`을 내지 않는다.
- 의학적 조언, 피부 질환 진단·치료 판단, 개인 피부 맞춤 추천은 하지 않는다.
- 금지 표현 점검 결과를 공식 심의 통과나 법적 확정으로 표현하지 않는다.
- 공공데이터포털 인증키는 사용자가 프로젝트 `.env`의 `DATA_GO_KR_SERVICE_KEY`에 넣는다. 키는 출력하거나 커밋하지 않는다.
- 원본 응답 전체는 커밋하지 않는다. 내보내기는 `build/cosmetics/`에 둔다.

## 단계

### 0단계 — 데이터 신뢰 게이트 (진행 중)

- [x] 공식 API 명세와 법령 원문 조사.
- [x] 응답 파서·클라이언트(`src/claimledger/sources/functional_cosmetics.py`)와 실측 스크립트(`scripts/audit_cosmetics.py`), 합성 테스트.
- [ ] **사용자 조치**: 공공데이터포털에서 「기능성화장품 보고품목정보」(15095680), 「기능성화장품 심사품목 정보」(15056939) 활용신청 후
      인증키를 `.env`에 `DATA_GO_KR_SERVICE_KEY=`로 저장.
- [x] (10/9) 가짜 키로 요청 주소 존재와 오류 형식 확인. 오류가 JSON·HTTP 403으로 오는 것을 반영해 클라이언트 수정.
- [x] (10/9) 키 없이 공개 화면에서 예비 표본 관찰(심사 70건, 보고 48건). 문구는 정형적이고 오래된 제품은 비어 있음. 게이트 측정은 아님.
- [ ] 탐침 실행(`--max-pages 1`)으로 실제 **정상** 응답 구조와 `EE_DOC_DATA` 형식 확인. 명세와 다르면 파서를 고친 뒤 진행.
- [ ] 전체 수집과 측정: 건수, `EE_DOC_DATA` 결측률, 품목일련번호 중복, 같은 품목명을 쓰는 품목 수, 취하 비율, 효능효과명 분포.
- [ ] 효능효과 문구 분석: 법정 11개 호 문구와 글자 그대로 같은 비율, 변형 유형, 한 제품에 여러 기능이 적힌 형태.
- [ ] 보고품목과 심사품목 두 목록의 관계와 중복 확인.
- [ ] 결과 기록(`docs/evidence/COSMETICS_DATA_GATE_<날짜>.md`)과 진행 여부 판단.

게이트 통과 조건: 효능효과 문구가 제품 대부분에 있고, 제품을 품목일련번호로 유일하게 확정할 수 있으며, 문구가 규칙으로 읽을 만큼 정형적이다.
어느 하나라도 안 되면 그 범위는 `검증 불가`로 두고 범위를 줄인다.

### 1단계 — 설계 결정 (0단계 결과를 본 뒤)

- 제품군 구분을 도메인에 넣는 방법(건강기능식품 / 기능성화장품 / 일반 화장품)과 기존 판정 엔진과의 경계.
- 대상 기능 선정. 건강기능식품에서 원료 3종으로 시작했듯이, 제품 수가 많고 문구가 정형적인 기능부터 고른다.
- 제품 검색·확정 흐름: 품목명과 업체명으로 후보를 보여 주고 사용자가 확정한다.
- 식약처 「화장품 표시·광고 관리 지침」 원문 확보와 금지 표현 규칙의 범위.

### 2단계 — 기능성화장품 판정 수직 슬라이스

- 공식 효능효과 파서(테스트 먼저), 광고 주장 추출의 화장품 어휘, 판정 규칙.
- 건강기능식품 엔진에서 확인된 교훈을 처음부터 적용한다: 문장 전체 일치, 허용 목록, 질병·의약품 표현 우선 차단.

### 3단계 — 일반 화장품 금지 표현 점검

- 지침 원문에 있는 표현만 규칙으로 만든다. 결과는 `근거 불일치` 또는 `검증 불가`뿐이다.

### 4단계 — 평가와 독립 검토

- 실제 제품 표본 + 생성 광고 문장 + 맹검 라벨 두 벌로 오인 승인을 잰다(claim-eval과 같은 절차).
- 독립 재검토에서 P1이 0건이 될 때까지 판정 범위를 넓히지 않는다.

## 알려진 위험

- 성분을 주어로 한 주장은 제품 데이터로 확인할 수 없다(두 API 모두 성분 목록이 없음).
- "목록에 없음"을 근거로 한 판정은 제품 식별 오류에 취약하다. 이름이 비슷한 다른 제품을 고르면 잘못된 `근거 불일치`가 나온다.
- 지침의 금지 표현은 개정된다. 규칙에 지침 개정일을 버전으로 남긴다.
