# 화장품 확장 계획

- 사용자 결정(2026-10-07): "여기서 화장품까지 판별 대상으로 넣자", "발표 기한 고려하지 않고 작업해도 된다".
- 브랜치: `cosmetics-data-gate`. 발표용 MVP(`phase-0-c003-data-gate`의 `71f3b30`)는 건드리지 않는다.
- 조사 기록: [화장품 공식 데이터소스 조사](../../evidence/COSMETICS_DATA_SOURCES_2026-10-07.md).

## 목표

화장품 광고의 주장을 공식 데이터와 대조해, 확인된 범위와 확인할 수 없는 범위를 근거영수증으로 보여 준다.
건강기능식품과 같은 원칙을 지킨다. 최우선 지표는 오인 승인율이고, 근거가 부족하면 `검증 불가`로 멈춘다.

## 지키는 제약

- 데이터 실측(0단계) 전에는 화장품 판정 규칙, 화면, 평가세트를 만들지 않는다.
- `확인됨`은 사용자가 확정한 제품의 공식 효능효과와 명시적 규칙이 일치할 때만 낸다.
- 일반 화장품(기능성 보고·심사가 없는 제품)에는 `확인됨`을 내지 않는다.
- 의학적 조언, 피부 질환 진단·치료 판단, 개인 피부 맞춤 추천은 하지 않는다.
- 금지 표현 점검 결과를 공식 심의 통과나 법적 확정으로 표현하지 않는다.
- 공공데이터포털 인증키는 사용자가 프로젝트 `.env`에 넣는다. 두 API의 키가 같으면 `DATA_GO_KR_SERVICE_KEY`, 다르면
  `DATA_GO_KR_SERVICE_KEY_REPORTED`·`DATA_GO_KR_SERVICE_KEY_REVIEWED`에 각각 넣는다. 키는 출력하거나 커밋하지 않는다.
- 원본 응답 전체는 커밋하지 않는다. 내보내기는 `build/cosmetics/`에 둔다.

### 3단계 — 일반 화장품 금지 표현 점검

- 지침 원문에 있는 표현만 규칙으로 만든다. 결과는 `근거 불일치` 또는 `검증 불가`뿐이다.

### 4단계 — 평가와 독립 검토

- 실제 제품 표본 + 생성 광고 문장 + 맹검 라벨 두 벌로 오인 승인을 잰다(claim-eval과 같은 절차).
- 독립 재검토에서 P1이 0건이 될 때까지 판정 범위를 넓히지 않는다.

## 알려진 위험

- 성분을 주어로 한 주장은 제품 데이터로 확인할 수 없다(두 API 모두 성분 목록이 없음).
- "목록에 없음"을 근거로 한 판정은 제품 식별 오류에 취약하다. 이름이 비슷한 다른 제품을 고르면 잘못된 `근거 불일치`가 나온다.
- 지침의 금지 표현은 개정된다. 규칙에 지침 개정일을 버전으로 남긴다.
