## A부. `claim-eval-v7`과 사람 라벨 (지금 진행)

지금까지의 평가 수치는 모두 AI 라벨이다. "오인 승인 0"이 사람 기준으로도 맞는지, 그리고 AI 라벨이 사람 판단과 얼마나 같은지 처음으로 잰다.

### 만들기

1. 표본: `scripts/build_ad_eval.py sample`, `--eval-id claim-eval-v7 --case-prefix C7 --seed 20261118`, v1~v6 제품 600개 제외, 광고 100개.
   v3~v6과 같은 설계다(시나리오·배치·역할표).
2. 사람 라벨 대상: `subset --seed 20261118 --size 50`. 시나리오마다 절반씩, 시드로 고른 광고 50개다. 문장을 쓰기 전에 고정한다.
3. 광고 문장: 홀수 사례는 Sonnet, 짝수 사례는 Opus 작성 에이전트가 역할표만 보고 쓴다. 작성 에이전트는 행 수만 보고한다.
4. AI 라벨: 맹검 AI 라벨러 두 개(Sonnet·Opus)가 100개 전체를 라벨한다. 판정별 개수만 보고한다.
5. 사람 라벨: `human-sheet`로 만든 50개 광고의 라벨지(AI 라벨러와 같은 판정 규칙)와 빈 `labels-human.csv`.
   - 라벨러는 사용자이고, 가능하면 약사나 표시광고 검토자 한 명을 더한다.
   - 엔진 결과, AI 라벨, 다른 사람의 라벨은 보지 않는다.
   - labeler 칸에는 이름 대신 역할을 쓴다(공개 저장소).
6. 개발자는 문장, AI 라벨, 사람 라벨을 읽지 않는다. 확인은 개수와 형식 검사만 한다.

### 채점 (사람 라벨이 들어온 뒤, 한 번)

공개 엔진을 채점하고 다음을 보고한다.

- 사람 라벨 기준:
  - 오인 승인 수(주장 아닌 문장 포함)와 정확한 95% 단측 상한.
  - `확인됨` 재현율.
  - 틀린 `근거 불일치`.
  - `근거 불일치` 재현율.
- AI 라벨과 사람 라벨의 비교:
  - 문장별 일치율과 Cohen's kappa.
  - 두 AI 라벨러가 모두 `확인됨`으로 본 문장 중 사람이 `확인됨`이 아니라고 본 수. AI 라벨이 사람보다 너그러우면 지금까지의

v7은 B부의 동결 시험으로 남긴다. 그래서 A부 채점에서 개발자는 요약 수치만 본다. 문장별 채점 파일은 `build/claim-eval-v7/`(Git 제외)에 두고,

### 채점 전에 정한 조치

1. 사람 라벨 기준 오인 승인이 1건이라도 있으면 P1로 다룬다. README에 그대로 적고 B부를 멈춘다. 고치는 순서는 실패 테스트, 새 평가세트,

2. 두 AI 라벨러가 모두 `확인됨`으로 본 문장 중 사람이 아니라고 본 것이 10% 이상이면, README의 AI 라벨 기준 수치 옆에 그 사실을 적는다.
   이후 평가세트에는 사람 라벨 표본을 붙인다.

## B부. LLM 맥락 문장 판독 (계획만; 구현은 사용자 승인 뒤)

2026-11-22 사용자 결정으로 B부는 Codex가 구현한다. 아래 설계·실패 처리·평가 기준을 따르며, SDK 설치·유료 호출·키·모델은 구현 전에
사용자에게 따로 승인받는다. 동결 시험은 v7이 아니라 새 평가세트 `claim-eval-v8`이다(아래 평가 기준).

### 측정으로 본 목표 (개발용 v6, 공개 엔진)

v6에서 옆 문장 때문에 보류된 정직한 주장 30개를, 막은 문장의 종류(`holding_sentences`)별로 나누면 다음과 같다.

| 막은 문장 | 주장 수 | LLM 판독으로 풀 수 있나 |
|---|---|---|
| 원료 주어 옆의 주어 없는 주장 | 9 (+고지 문구와 겹침 1) | 아니오. 생략된 주어를 정하는 규칙은 넣지 않는다(AGENTS.md) |
| 섭취법 문장 | 7 | 섭취량 대조가 있으면 |
| 주장처럼 읽힌 고지 문구(질병 단어 때문) | 7 (+소개와 겹침 1, +주어 없는 주장과 겹침 1) | 고지 문구 판독이 있으면 |
| 소개 문장 | 3 (+고지 문구와 겹침 1) | 예 |
| 끝까지 읽지 못한 주장 | 2 | 아니오(B부 밖, 풀어 쓴 공식 문구) |

- 규칙이 읽지 못한 섭취법 문장 17개는 모두 횟수·양 표현("하루 한 번", "2캡슐")을 담고 있었다. "숫자가 없으면 통과" 같은 교차 확인으로는
  섭취법을 하나도 풀지 못한다.
- 소개 문장 14개 중 6개에도 숫자("100억 CFU", "1000mg")가 있다. 함량·보장 수치는 그대로 막는다.
- 섭취법은 공식 섭취방법(C003 `intake_method`)과 횟수·양이 같은지로만 푼다. 대상 원료 제품 13,628개 중 10,907개에 "1일 N회"가 있다.
  B1에서 파서가 실제로 읽는 비율을 먼저 잰다.

### 설계

LLM은 문장을 "읽지 못함"에서 "주장 없는 맥락 문장"으로 옮기는 일만 한다. `확인됨`은 지금처럼 규칙만 낸다.

- B1 소개 문장: LLM이 문장 하나(광고 전체가 아님)를 고정 JSON 스키마로 분류한다.
  - 역할: 섭취법, 소개, 고지, 주장, 기타.
  - 표시: 건강 효과, 기간·시점, 양·횟수, 대상자, 조건, 비교·보장, 부정·반박.
  - 판독 조건은 세 가지를 모두 만족하는 것이다.
    - 역할이 소개이고 표시가 모두 거짓.
    - 독립 호출 두 번의 결과가 같음.
    - 규칙 교차 확인 통과: 효과·강도·질병 단서, 숫자·수량 단위, 부정어, 물음표, 조건 어미가 없음.
- B2 섭취법 문장: LLM이 횟수·양·단위·때(식후 등)를 뽑는다. 규칙이 공식 섭취방법을 파싱한 값과 같고, 그 밖의 내용(효과, "이면 충분", 기간)이
  없을 때만 판독한다. 공식 섭취방법을 읽지 못하면 판독하지 않는다.
- B3 고지 문구(B1·B2가 기준을 넘은 뒤 따로 판단): 역할이 고지이고 효과 주장이 없다는 LLM 판독과, 문장의 낱말이 모두 고지 문구 어휘 안에 있다는
  규칙 확인이 함께 필요하다. "의약품은 아니지만 치료합니다" 같은 꼴이 위험 경로라 독립 재검토의 첫 대상이다.
- B부 밖: 풀어 쓴 공식 문구, 꾸민 주어, 주어 생략, 화장품. 주장의 뜻 자체를 다루므로 별도 결정이다.

### 실패 처리·재현성 (추천 4번)

- API 오류, 시간 초과, 거절, 스키마 불일치, 두 호출의 불일치는 모두 그 문장을 "읽지 못함"으로 둔다. 실패를 안전 판정으로 바꾸지 않는다
  (AGENTS.md).
- 판독 결과는 (문장 SHA-256, 모델 ID, 프롬프트 버전)으로 저장한다. 같은 광고를 다시 넣으면 같은 답이 나온다.
- 영수증의 "끝까지 읽지 못한 문장" 옆에 "AI 보조 판독" 칸을 둔다. 판독한 문장, 역할, 모델 ID, 프롬프트 버전, 판독 시각을 적는다.
  규칙 버전 칸에 판독기 버전을 더한다.
- 기본 테스트는 저장한 응답(fixture)으로 돈다. 유료 호출은 네트워크 테스트로 분리하고, 사용자가 `.env`에 키를 넣은 뒤에만 돈다.
- 기본 실행은 LLM 없이 지금과 같다. LLM 판독은 명시적으로 켤 때만 쓴다.

### 평가 기준 (B부를 채점하기 전에 고정; `claim-eval-v8`, 공개 엔진과 한 번 비교)

2026-11-22 변경: 시험 세트를 v7에서 v8로 바꾸고 사람 라벨을 뺐다(사용자 결정, 위 A부 기록). 나머지 기준은 그대로다.
v8은 v7과 같은 설계(`scripts/build_ad_eval.py`, v1~v7 제품 제외)로 B부를 개발하지 않는 세션이 만든다. B부 개발자(Codex)는 v8의 문장·라벨·채점 파일을
읽지 않는다. 개발에는 v3~v7을 쓴다.

1. 오인 승인 0: AI 본·엄격 라벨 모두, 주장 아닌 문장 포함.
2. LLM이 판독한 문장 중 어느 라벨에서든 `none`이 아닌 문장이 0개다.
3. 옆 문장 때문에 보류된 `확인됨` 라벨 문장이 공개 엔진보다 3분의 1 이상 줄고, `확인됨` 재현율이 오른다(AI 본 라벨).
4. 틀린 `근거 불일치`가 늘지 않는다.
5. 위험 문장 묶음: `engine_diff.py`의 옆 문장 묶음에 든 위험 문장(기간, 부정, 섭취량, 조건)을 하나도 판독하지 않는다.
6. 저장한 판독으로 다시 채점하면 결과가 바이트 단위로 같다.

채점 전 독립 재검토(읽기 전용)를 받는다. 하나라도 못 맞추면 판독을 끄고 결과를 기록한다.

### 사용자 결정이 필요한 것

- Anthropic SDK 설치(새 의존성: 이 단계의 재현성·운영성 근거를 문서에 남김)와 유료 호출.
- API 키: 사용자가 프로젝트 `.env`에 직접 넣는다. 대화에 붙여 넣지 않는다.
- 모델: 기본은 `claude-opus-5-5`. 더 싼 모델은 개발용 세트에서 같은 결과가 측정되고 사용자가 승인할 때만 쓴다.
- 사람 라벨 시간: 50개 광고(약 115문장). 2026-11-22 사용자 결정으로 생략했다.
