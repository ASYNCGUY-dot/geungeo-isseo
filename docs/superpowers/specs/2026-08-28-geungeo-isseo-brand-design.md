# 근거있어 브랜드·명명 설계

- 상태: 승인됨
- 결정일: 2026-08-28
- 최초 고객: 건강기능식품 광고의 근거를 직접 확인하려는 일반 소비자
- 확장 방향: 소비자 서비스에서 기업용 광고 사전검수로 확장

## 1. 결정

프로젝트와 소비자 서비스의 공식 이름은 **근거있어**로 한다. 서비스가 주장별 검증
결과로 발급하는 대표 결과물은 **근거영수증**으로 부르고, 결정적 검증 로직과 파이썬
패키지의 기술명은 **ClaimLedger**와 `claimledger`를 유지한다.

| 대상 | 확정 이름 | 사용 위치 |
|---|---|---|
| 소비자 서비스·프로젝트 표시명 | 근거있어 | README, 프로젝트 브리프, 화면, 발표자료, 위키 |
| 질문형 브랜드 문장 | 이 광고, 근거 있어? | 온보딩, 입력 CTA, 마케팅 문구 |
| 대표 결과물 | 근거영수증 | 주장별 판정 리포트와 내보내기 |
| 내부 검증엔진 | ClaimLedger | 기술 설계, 아키텍처, 감사 로그 |
| 파이썬 import 패키지 | `claimledger` | `src/claimledger`, 테스트와 CLI import |
| 폴더·향후 원격 저장소 슬러그 | `geungeo-isseo` | 로컬 프로젝트 루트와 GitHub 저장소 후보명 |

핵심 슬로건은 **건강광고, 말보다 근거부터.**로 한다.

## 2. 이름의 역할을 분리하는 이유

`근거있어`는 소비자가 광고를 보고 실제로 품는 질문이라 기억하기 쉽고, 서비스가
답을 확정할 수 없는 경우에도 과장된 보증을 하지 않는다. `근거영수증`은 출처,
조회시각, 제품 식별자, 적용 규칙, 불확실성을 묶어 보여주는 결과물의 성격을 정확히
표현한다. `ClaimLedger`는 현재 코드와 테스트가 사용하는 내부 엔진명으로 남겨 기술
연속성과 감사 가능성을 보존한다.

## 3. 문구 규칙

- 현재 프로젝트를 소개할 때 `근거영수증 / ClaimLedger`를 제품명처럼 병기하지 않는다.
- 첫 소개는 `근거있어`로 시작하고 필요한 경우에만
  `ClaimLedger 검증엔진이 근거영수증을 발급한다`고 설명한다.
- `근거영수증`은 서비스 전체가 아니라 주장별 결과물에만 사용한다.
- `ClaimLedger`는 소비자 화면의 주 브랜드로 사용하지 않는다.
- `사실`, `안전`, `효과 있음`, `검증 완료`를 브랜드가 보증하는 것처럼 표현하지 않는다.
- 근거가 부족하거나 제품 신원이 확정되지 않으면 기존 원칙대로 `근거 부족` 또는
  `검증 불가`를 출력한다.

## 4. 저장소 변경 경계

- 로컬 프로젝트 폴더를 `_persnal V1`에서 `geungeo-isseo`로 바꾼다.
- `[project].name`은 배포 프로젝트명을 나타내도록 `geungeo-isseo`로 바꾼다.
- `src/claimledger`와 모든 `from claimledger ...` import는 내부 엔진 계약이므로 바꾸지
  않는다.
- 현재 운영 문서와 위키 포인터는 새 이름과 새 절대경로로 갱신한다.
- 과거 계획·의사결정에서 당시 작업명을 설명하는 문장은 역사적 맥락을 보존하되,
  현재 이름으로 연결되는 안내를 추가한다.
- 원격 저장소는 현재 구성되어 있지 않으므로 새 원격을 만들거나 push하지 않는다.

## 5. 검증 조건

이름 변경은 다음 조건이 모두 충족될 때 완료로 본다.

1. 현재 README, 브리프, 인수인계, AGENTS, 위키 정본이 `근거있어`를 서비스명으로 쓴다.
2. 프로젝트 루트와 문서의 현재 경로가 `geungeo-isseo`로 일치한다.
3. `pyproject.toml`의 배포 프로젝트명은 `geungeo-isseo`이고 import 패키지는
   `claimledger`로 정상 동작한다.
4. 위키의 프로젝트 정본과 현재 인수인계 파일명·링크에 끊어진 참조가 없다.
5. linked worktree가 이동 후에도 같은 브랜치와 HEAD를 가리킨다.
6. 전체 테스트, Ruff, `git diff --check`, Git 상태 점검을 이동 후 새 경로에서 다시
   실행한다.
