## 바뀐 것

1. **부분 일치로 문장 전체 승인 금지.** 기존에는 여러 효과 후보 중 하나만 공식 원문에 있어도
   전체 문장을 `confirmed`로 만들었다. 이제 긍정 판정 직전에 원문 전체가 지원하는 단일 도움 표현과
   맞는지 검사한다. 추가 효과·부정·질문·수치·대상 조건·다른 원료 주체는
   `unverifiable / CLAIM_SCOPE_UNRESOLVED`로 보류하고 공식 인용을 붙여 통과한 것처럼 보이지 않는다.
2. **부정 어미로 문장 전체 누락 금지.** "혈행을 확실히 개선하며 부작용이 없습니다"를 삭제하던 경로를
   막았다. 정확히 인식한 순수 의약품 면책문만 제외한다. 이것은 모든 건강·안전 주장 추출을 구현한 것이 아니다.
3. **공식 원료 귀속 보수화.** 대괄호 뒤 콜론/원료명 단독 줄이 나타나면 새 블록으로 처리한다.
   부분 문자열이나 공동 헤더를 단일 원료로 인정하지 않는다. 해석하지 못한 인라인 콜론, 부정·제외·대신·삭제·미인정,
   도움 술어 없는 문구는 긍정 근거로 쓰지 않는다. 후속 수정은 공식 절 전체가 지원하는
   효과 목록+긍정 술어로 소비될 때만 귀속한다. 정상적인 마침표 문장/번호 목록은 지원하되,
   '기억력 개선은 검토 중이며 혈행 개선에 도움'이나 해석되지 않은 대시 헤더를 승인하지 않는다.
   공식 필드에 부정·삭제·미인정 표현이 있으면 적용 범위를 추측하지 않고 필드 전체의 긍정 귀속을 보류한다.
   귀속에는 같은 원료 블록의 모든 줄이 지원 문형이어야 한다. 내용 없는 미지원 헤더도
   문맥 누락 가능성으로 보류한다. 마침표(유니코드 정규화로 마침표가 되는 문자 포함)는
   효과 목록 구분자가 아니며 각 문장에 별도 긍정 술어가 있어야 한다.
   광고의 줄바꿈은 문장 경계로 보지 않아 주체나 뒤쪽 제한 문구를 떨어뜨리지 않는다.
4. 영수증에 문장 전체의 미확인 범위를 설명하고 버전을 구분한다:
   `claim-extract-v1.2`, `official-function-v2.2`, `claim-verdict-v1.1`.
   1차 중간 커밋의 추출 v1.1/공식 파서 v2.1과 구분한다.
