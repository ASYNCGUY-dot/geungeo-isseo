# 화장품 확장 — 공식 데이터소스 조사 — 2026-10-07

사용자 결정("화장품까지 판별 대상으로 넣자", "발표 기한 고려하지 않고 작업해도 된다")에 따라 화장품 확장을 시작했다.
이 문서는 판정 규칙을 만들기 전에 **공식 데이터가 무엇을 제공하는지** 조사한 기록이다. 조사일은 2026-10-07이다.
실제 API 호출은 아직 하지 못했다(공공데이터포털 인증키 없음). 아래 내용은 공개 명세와 법령 원문을 읽은 결과다.

## 한 줄 결론

기능성화장품은 건강기능식품의 C003에 해당하는 **제품별 공식 효능효과 데이터가 있다.** 일반 화장품은 그런 데이터가 없다.
따라서 `확인됨`은 기능성화장품의 공식 효능효과 범위 안에서만 가능하고, 일반 화장품 광고는 금지 표현 점검까지만 가능하다(설계 방향, 실측 전 가정).

## 확인된 사실

### 1. 기능성화장품의 법정 범위

출처: 화장품법 시행규칙 제2조, [시행 2026. 4. 2.] [총리령 제2109호, 2026. 3. 31., 일부개정], 국가법령정보센터에서 원문 확인.
기능성화장품은 다음 11개 호다.

1. 멜라닌색소 침착을 방지하여 기미·주근깨 등의 생성을 억제함으로써 피부의 미백에 도움을 주는 기능
2. 침착된 멜라닌색소의 색을 엷게 하여 피부의 미백에 도움을 주는 기능
3. 피부에 탄력을 주어 피부의 주름을 완화 또는 개선하는 기능
4. 강한 햇볕을 방지하여 피부를 곱게 태워주는 기능
5. 자외선을 차단 또는 산란시켜 자외선으로부터 피부를 보호하는 기능
6. 모발의 색상을 변화(탈염·탈색 포함)시키는 기능. 일시적으로 색상을 변화시키는 제품은 제외
7. 체모를 제거하는 기능. 물리적으로 제거하는 제품은 제외
8. 탈모 증상의 완화에 도움을 주는 화장품. 코팅 등 물리적으로 모발을 굵게 보이게 하는 제품은 제외
9. 여드름성 피부를 완화하는 데 도움을 주는 화장품. 인체세정용 제품류로 한정
10. 피부장벽의 기능을 회복하여 가려움 등의 개선에 도움을 주는 화장품
11. 튼살로 인한 붉은 선을 엷게 하는 데 도움을 주는 화장품

조사 중 본 기사는 "총 10종"이라고 적었으나 원문은 11개 호다. 규칙은 원문 기준으로 만든다.

## 2026-10-09 추가 확인 — 키 없이 한 준비

사용자 요청("다음 순서 진행해줘") 시점에 프로젝트 `.env`에는 `DATA_GO_KR_SERVICE_KEY`가 없었다(파일 수정일 2026-08-23, 환경변수에도 없음).
그래서 **API 전체 수집과 게이트 측정은 아직 하지 못했다.** 아래는 키 없이 가능한 확인이다.

### 요청 주소와 오류 형식 (가짜 키로 확인)

- 두 요청 주소 모두 존재한다. 가짜 키를 보내면 HTTP 403과 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`가, 경로를 일부러 틀리면 HTTP 400과 `NO_OPENAPI_SERVICE_ERROR`가 온다.
- **가정 수정**: 게이트웨이 오류가 XML로 온다고 가정했으나 실제로는 JSON 본문
  (`{"OpenAPI_ServiceResponse": {"cmmMsgHeader": {"errMsg": ...}}}`)과 HTTP 403/400이었다.
  클라이언트가 이유 코드를 함께 알려 주도록 고쳤다(자유 문장은 옮기지 않고 대문자 코드만 옮긴다).
- 정상 응답의 JSON 구조는 여전히 미확인이다.

### 의약품안전나라 공개 화면 표본 (예비 관찰, 게이트 측정이 아님)

키가 필요 없는 공개 화면에서 효능효과 문구를 소량 읽었다. 목록의 여러 지점에서 연속된 제품을 골랐으므로 **무작위 표본이 아니다.**
비율을 전체에 그대로 적용하면 안 된다. 원자료는 `build/cosmetics/public-sample-*.json`(추적 안 함)에 있다.

| | 심사 품목 | 보고 품목 |
|---|---|---|
| 화면에 표시된 전체 건수 | 20,728 | 183,080 |
| 읽은 제품 | 70 (심사일 2006~2026) | 48 (보고일 2012~2026) |

- **문구는 매우 정형적이다.** 심사 표본의 89줄은 글머리 기호(`-`, `-.`, `1.`), 괄호, 띄어쓰기, 마침표를 걷어 내면 모두 다음 문장 중 하나였다.
  - `자외선으로부터 피부를 보호한다` 39줄
  - `피부의 미백에 도움을 준다` 24줄, `피부 미백에 도움을 준다` 1줄
  - `피부의 주름개선에 도움을 준다` 18줄
  - `모발의 염모(색상)` 3줄
  - `여드름성 피부를 완화하는 데 도움을 준다` 2줄
  - `탈모증상의 완화에 도움을 준다` 1줄
  - `피부장벽의 기능을 회복하여 가려움 등의 개선에 도움을 준다` 1줄
- 보고 표본 40건의 문장도 같은 네 가지(미백 28, 주름개선 21, 염모 9, 자외선 7)뿐이었다.
- **제품 문구는 법조문 문구와 다르다.** 시행규칙은 "주름을 완화 또는 개선하는 기능"이라고 쓰지만 제품 문구는 "피부의 주름개선에 도움을 준다"다. 규칙은 제품 문구를 기준으로 만든다.
- **자외선 지수 표기가 제각각이다.**
  - 심사: `(SPF50+, PA++++)`, `(SPF 50+, PA ++++)`, `(SPF50+ PA++++)`, `(SPF50+, PA++++, 지속내수성)`, 지수 없는 줄 1건.
  - 보고: `(SPF: 50+, PA: ++++ )`. 여러 기능이 있으면 지수가 자외선 문장이 아니라 맨 끝 문장 뒤에 붙는다(5건).
- **공식 자료에도 오기가 있다.** `(SP33, PA+++)`, `(SPF: SPF50+, PA: ++++ )`.
- **오래된 제품은 효능효과가 비어 있다.** 심사 2006~2009년, 보고 2012년 표본에서 확인했다. 이런 제품은 `검증 불가`로 둔다.
- 보고 품목의 문장이 지나치게 균일하고 `()`만 남는 경우가 있는 것으로 보아, 보고 품목의 화면 문구는 구조화 항목(`EFFECT_YN1~3`, `SPF`, `PA`)에서
  만들어지는 것으로 보인다(추론). API의 `EE_DOC_DATA`가 이 화면 문구와 같은지는 키로 확인해야 한다.

### 설계에 주는 의미 (예비)

- 기능성화장품 효능효과는 건강기능식품 원문보다 훨씬 규칙적이라, 허용 목록 방식의 파서로 대부분을 읽을 수 있을 가능성이 높다.
- 공식 강도는 "도움을 준다"와 "보호한다"다. 건강기능식품의 "도움을 줄 수 있음"과 다르므로 강도 규칙을 그대로 옮기면 안 된다.
- 자외선 차단은 지수(SPF, PA, 내수성)까지 대조해야 한다. 광고가 "SPF50+"라고 쓰면 공식 지수와 숫자가 같아야 한다.
- 염모는 색상까지 공식 문구에 들어 있다.

## 확인되지 않은 것 (실측 전)

- 실제 **정상** 응답의 JSON 구조(오류 응답 형식은 10/9에 확인). 명세는 `body.items.item`을 적고 있으나 목록 형태일 수 있다. 파서는 명세 구조와 흔한 목록 변형만 받고 나머지는 오류로 멈춘다.
- `EE_DOC_DATA`의 형식(일반 글자인지, 문서 마크업인지)과 공개 화면 문구와의 일치 여부.
- 전체 건수, `EE_DOC_DATA` 결측률, 효능효과 문구의 정형성(11개 호 문구와 얼마나 같은지).
- `EE_CODE`·`EE_NAME`의 값 목록과 11개 호의 대응. `EFFECT_YN1~3`은 미백·주름개선·자외선 세 가지뿐이다.
- 같은 품목명이 여러 품목일련번호에 쓰이는 정도(제품 식별 가능성), 취하된 보고의 비율.
- 보고품목과 심사품목 두 목록의 중복·관계.
- `numOfRows` 상한과 개발계정 하루 호출 한도(안내상 10,000건) 안에서 전체 수집이 되는지.

## 설계에 주는 의미 (추론, 실측으로 검증할 가정)

- **기능성화장품은 원료 귀속 문제가 없다.** 효능효과가 제품 단위로 보고·심사되므로, "이 제품은 주름 개선에 도움"은 제품의 공식 효능효과와 직접 대조할 수 있다.
  건강기능식품에서 가장 어려웠던 "이 문구가 어느 원료의 것인가"가 생기지 않는다.
- **두 API 모두 성분 목록을 주지 않는다.** "나이아신아마이드가 미백에 도움"처럼 성분을 주어로 한 주장은 제품 데이터로 확인할 수 없다.
  기능성화장품 고시 원료와 함량 기준이 따로 필요하고, 제품의 실제 함량은 공개되지 않는다.
- **일반 화장품은 `확인됨`을 낼 근거가 없다.** 제품별 효능 등록 제도가 없으므로 금지 표현에 해당하면 `근거 불일치`, 그 밖은 `검증 불가`만 가능하다.
- **일반 화장품이 기능성 효능을 표방하는 광고**(예: 기능성 보고가 없는 제품의 "주름 개선")는 제품 확정 후 "보고·심사 목록에 없음"으로 잡을 수 있다.
  단, 목록에 없다는 판단은 제품 식별이 정확할 때만 성립한다.

## 실측 준비 상태

- `src/claimledger/sources/functional_cosmetics.py`: 두 API의 응답 파서와 클라이언트. 주소·사업자등록번호는 버리고 식별·효능효과 항목만 남긴다.
- `scripts/audit_cosmetics.py`: 전체 수집, JSONL 내보내기(`build/cosmetics/`, 추적 안 함), 건수·결측·중복·이름 충돌·취하·효능효과 분포 측정.
- `tests/test_functional_cosmetics.py`: 합성 응답 21개 테스트, 네트워크 없음.
- 실행에는 `.env`의 인증키가 필요하다. 사용자가 공공데이터포털에서 위 두 API를 활용신청해야 한다. 2026-10-09 현재 키가 없어 미실행이다.
- 인증키 변수(2026-10-11): 두 API의 키가 같으면 `DATA_GO_KR_SERVICE_KEY` 하나만 채운다. 포털이 API마다 다른 키를 보여 주면
  `DATA_GO_KR_SERVICE_KEY_REPORTED`(보고품목)와 `DATA_GO_KR_SERVICE_KEY_REVIEWED`(심사품목)에 각각 넣는다. API별 변수가 공용 변수보다 우선한다.
  포털이 계정당 키 하나를 주는지 API마다 주는지는 확인하지 못했다(처음에는 하나라고 가정해 칸을 하나만 만들었다).

```powershell
.venv\Scripts\python.exe scripts\audit_cosmetics.py --env-file "%USERPROFILE%\Desktop\DONGA AI LAB\DONGA KDT 3RD PROJECT\geungeo-isseo\.env" --max-pages 1
.venv\Scripts\python.exe scripts\audit_cosmetics.py --env-file "%USERPROFILE%\Desktop\DONGA AI LAB\DONGA KDT 3RD PROJECT\geungeo-isseo\.env"
```

첫 명령은 한 페이지만 읽어 응답 구조와 키가 맞는지 확인하는 탐침이고, 둘째 명령이 전체 수집이다.
