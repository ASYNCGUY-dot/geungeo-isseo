# 근거영수증 / ClaimLedger 프로젝트 브리프

- 결정일: 2026-08-22
- 프로젝트 기간: 2026-08-26 ~ 2026-10-12
- 진행 형태: 개인 프로젝트
- 교육과정 주제: 미디어 검수 에이전트
- 제품 상태: Phase 0 안전 기반 구현, C003 라이브 접근 전 제한 경로 결정

## 1. 한 문장 정의

건강기능식품 광고를 입력하면 광고의 주장을 하나씩 분리하고, 공식 제품 정보·공식 기능성 범위·선별된 과학적 근거와 대조하여 **무엇이 확인됐고 무엇은 확인할 수 없는지 근거 영수증 형태로 보여주는 서비스**다.

## 2. 해결하려는 문제

건강기능식품 광고와 후기는 강한 표현을 사용하지만 사용자는 다음을 구분하기 어렵다.

- 그 제품에 실제로 등록된 기능성인지
- 특정 원료에 대한 연구를 완제품 효과처럼 말하는지
- “도움을 줄 수 있음”을 “개선한다”로 확대했는지
- 연구 대상·용량·기간이 광고 내용과 같은지
- 논문이 있다는 사실과 해당 주장이 확인됐다는 사실이 같은지
- 협찬·체험단 표시는 있으나 독립적인 후기처럼 보이는지

현재의 문제는 정보 부족만이 아니라 **근거의 종류와 적용 범위가 섞여 있다는 것**이다.

## 3. 사용자 우선순위

1. 결과의 정확성과 신뢰성
2. 틀릴 위험을 통제하고 사용자에게 노출하지 않는 구조
3. 유료로 사용할 이유가 있는 수익화 가능성
4. 기술 난도, 기능 수, 화려함, 기발함

서비스의 경쟁력은 “항상 답하는 AI”가 아니라 **확인할 수 있을 때만 답하고, 그 판단 경로를 재현할 수 있는 시스템**이다.

## 4. MVP 사용자 흐름

1. 사용자가 광고 캡처 또는 텍스트를 입력한다.
2. OCR 또는 텍스트 파서가 원문을 보존한다.
3. LLM이 검증 가능한 주장을 원자 단위로 추출하고 구조화한다.
4. 시스템이 제품 후보를 제시한다.
5. 사용자가 제조사와 제품명을 보고 정확한 제품을 선택한다.
6. 공식 제품 정보, 공식 기능성 문구, 선별된 과학적 근거를 검색한다.
7. 규칙 엔진이 표현 강도, 대상, 성분, 용량, 기간, 결과지표의 일치 여부를 판정한다.
8. 결과를 주장별 근거 영수증으로 출력한다.
9. 필수 정보가 없거나 규칙이 다루지 못하면 확정하지 않고 검토 필요 상태로 종료한다.

## 5. 공개 판정 상태

| 상태 | 사용 조건 |
|---|---|
| 확인됨 | 제품 신원과 근거 출처가 확정됐고 광고 주장이 허용 범위와 명시적으로 일치 |
| 근거 불일치 | 관련 근거는 있으나 표현 강도·대상·용량·기간·제품 범위가 불일치 |
| 근거 부족 | 관련 자료는 있지만 해당 주장을 지지할 수준이나 직접성이 부족 |
| 검증 불가 | 제품 신원, 원문, 공식 데이터 또는 판정 규칙 중 필수 요소가 없음 |
| 직접 반박됨 | 신뢰 가능한 근거가 광고의 핵심 주장을 직접 부정 |

종합 별점이나 하나의 제품 점수는 MVP에서 제공하지 않는다. 한 광고에 확인된 주장과 확인되지 않은 주장이 동시에 존재할 수 있기 때문이다.

## 6. 근거의 세 층

### A. 규제·공식 사실

- 식약처 제품 신고정보
- 공식 인정 기능성 문구
- 섭취방법과 주의사항
- 회수·판매중지 정보
- 공식 심의·법령·행정처분 자료

### B. 과학적 근거

- 체계적 문헌고찰·메타분석
- 무작위 대조시험
- 관찰연구
- 동물·세포 연구
- 연구 대상, 용량, 기간, 결과지표, 한계

### C. 제품별 증거

- 해당 완제품 자체의 시험자료
- 제조번호별 시험성적서
- 제3자 시험기관 검사

A와 B가 있어도 C를 자동으로 증명하지 않는다. 원료 연구를 해당 완제품의 품질·효능으로 확대하지 않는다.

## 7. AI와 규칙의 역할 분리

AI가 맡는 일:

- 이미지·텍스트에서 광고 주장 후보 추출
- 주장 구조화와 동의어 정규화
- 관련 근거 후보 검색과 요약 초안
- 사람이 검토할 불명확 사례 분류

결정적 코드가 맡는 일:

- 제품 신원 확인 여부
- 수치와 단위 변환
- 공식 문구와 표현 강도 비교
- 대상·용량·기간·근거 층 일치 여부
- 판정 상태 선택
- 출처·규칙 버전·조회시각 저장

전문가가 맡는 일:

- 판정 규칙과 라벨링 지침 승인
- 상충하거나 고위험인 사례 검토
- 정답 평가세트 감수
- 오류 사례의 원인 분석과 규칙 변경 승인

## 8. MVP 범위

### 포함

- 건강기능식품 광고 이미지·텍스트 입력
- 제품 후보 검색과 사용자 확인
- 주장 추출 및 구조화
- 식약처 공식 제품·기능성·회수정보 대조
- 3~5개 대표 원료의 선별된 과학적 근거 카드
- 주장별 판정과 출처 공개
- 판정 보류와 전문가 검토용 큐의 데이터 구조
- 평가세트와 오인 승인률 측정
- FastAPI, React, LangGraph, RAG, Docker를 목적에 맞게 사용

초기 원료 후보는 루테인·지아잔틴, 오메가3, 프로바이오틱스다. 최종 선정은 C003 실측에서 제품 수와 핵심 필드 완전성을 확인한 뒤 3~5개로 고정한다.

### 제외

- 개인 맞춤 효능 보장
- 복용 중인 의약품과의 상호작용 판정
- 질병 진단·치료·예방 조언
- 개인별 제품 처방 또는 판매
- 화장품과 일반 식품 전체로 범위 확대
- 실물 제품을 검사하지 않은 함량·순도·오염 판정
- 공식 광고 심의 또는 법률 판단의 대체

## 9. 정확도와 출시 게이트

핵심 지표는 `False Clearance Rate`다.

```text
False Clearance Rate
= 실제로는 확인할 수 없거나 불일치인 주장 중 시스템이 “확인됨”으로 통과시킨 비율
```

MVP 공개 조건:

- 제품 신원 미확정 상태에서 `확인됨` 결과 0건
- 출처와 적용 규칙이 없는 `확인됨` 결과 0건
- 100건 고정 평가세트에서 오인 승인 0건
- 평가 데이터와 실제 데모 입력을 분리
- 모든 결과에 원문, 출처, 조회시각, 규칙 버전 표시
- API·LLM·파서 실패 시 성공 상태로 폴백하는 경로 0건
- 판정 커버리지와 `검증 불가` 비율을 정확도와 함께 공개

100건에서 오인 승인 0건이어도 “정확도 100%”라고 표현하지 않는다. 단순 3/n 근사에 따르면 관측 오류가 0일 때 95% 상한은 약 3%이므로 표본 밖 위험을 명시한다.

## 10. 데이터 상태와 첫 번째 게이트

2026-08-22 실측:

- 식약처 `I0490` 회수·판매중지: 정상, 총 372건
- 식약처 `C003` 건강기능식품 품목제조신고: 키는 유효하지만 활용신청 필요 상태
- 식약처 `I2710` 건강기능식품 품목분류정보: 원료 단위이며 활용신청 필요 상태
- PubMed E-utilities: 사용 가능, 연구유형·MeSH 메타데이터 확인
- 네이버 블로그 검색과 본문 추출: 가능하지만 협찬 표시가 없다고 내돈내산으로 판정할 수 없음
- 네이버 쇼핑·쿠팡 자동수집: 봇 차단을 확인했으므로 MVP는 사용자 캡처 입력을 사용

프로젝트의 첫 구현은 C003 라이브 커버리지 감사다. 다음을 측정하기 전 전체 제품 매칭 기능을 설계하지 않는다.

- 전체 레코드 수
- 제품명·업체명·주된기능성·원재료·섭취방법의 결측률
- 제품을 유일하게 식별할 공식 필드
- 초기 원료 후보별 제품 수
- 동일 이름·동일 업체 중복 패턴

### 2026-08-23 Phase 0 실행 결과

- 오프라인 파서·제품 확인·판정 불변식·오인 승인 지표: `24 passed`, 커버리지 `92%`
- C003 라이브 감사: 프로세스 환경에 `FOODSAFETY_API_KEY`가 없어 호출 전에 `BLOCKED`
- API 결과 코드와 전체 건수·필드 결측률·후보 제품 수: 아직 측정되지 않음
- 현재 결정: `LIMIT_TO_USER_SUPPLIED_LABELS`

이 제한 경로에서 사용자가 제공한 라벨은 `user-provided evidence`로 표시하며 공식 C003
제품 레코드로 표현하지 않는다. C003 키 설정 후 동일 감사 명령으로 `INFO-000`과 전체
커버리지를 확인하면 제품 중심 MVP 계속 여부를 다시 결정한다.

## 11. 기술 구조

```text
광고 캡처/텍스트
  → 원문 보존 및 OCR
  → LLM 주장 구조화
  → 제품 후보 검색
  → 사용자 제품 확정
  → 공식 데이터 + 근거 카드 검색
  → 결정적 규칙 엔진
  → 위험 게이트
      ├─ 조건 충족: 근거 영수증 발급
      └─ 조건 미충족: 검증 불가/전문가 검토
  → 평가 로그와 감사 추적
```

예상 기술:

- Backend: Python, FastAPI, Pydantic
- Agent orchestration: LangGraph
- Retrieval: 임베딩 검색 + 메타데이터 필터 + 명시적 임계값 검증
- Frontend: React + TypeScript
- Storage: 개발 단계 SQLite 또는 파일 fixture, 구조 확정 후 PostgreSQL 검토
- Testing: pytest, 프론트 단위테스트, 고정 평가세트
- Delivery: Docker, docker compose, CI

DB와 임베딩 모델은 데이터 게이트와 벤치마크 결과가 나온 뒤 선택한다. 배운 기술을 모두 넣기 위해서가 아니라 각 기술이 정확도·재현성·운영성 중 하나를 개선할 때만 채택한다.

## 13. 실제 출시 로드맵

### 1단계: 현재 프로젝트

광고 주장과 공식·과학적 근거의 일치 여부만 검증한다.

### 2단계: 전문가 거버넌스

약사·영양사·식품 표시광고 전문가가 판정 규칙, 정답 데이터, 고위험 예외를 검수한다. 전문가는 모든 건을 수작업하는 사람이 아니라 자동화의 허용 경계를 책임지는 사람이다.

### 3단계: 개인 복용관리

성분 중복, 총섭취량, 상한 초과 가능성, 의약품 상호작용을 추가한다. 적법한 자격·영업·개인정보 처리 구조와 전문가 상담 전환이 전제다.

### 4단계: 제품 실물 검증

공인 시험·검사기관과 연계하여 제조번호별 함량·순도·오염 검사 결과를 제공한다. 전문가 의견으로 실험실 검사를 대신하지 않는다.

### 5단계: 임상 기능 분리

질환·검사 수치·진단·치료 목적 기능은 의사와 별도 규제 검토를 포함한 독립 제품으로 다룬다.

## 14. 수익모델

- B2C 구독: 광고 근거 영수증, 가족 제품 보관함, 공식 회수정보 알림
- 전문가 유료 검토: 자동 판정이 보류된 사례의 약사·영양사 검수
- B2B SaaS: 제조사·대행사·인플루언서의 광고 초안 사전점검과 감사로그
- API: 커머스·콘텐츠 플랫폼의 게시 전 위험문구 검사
- 시험기관 제휴: 제조번호별 실물 검사 리포트

기업이 비용을 지불하는 대상은 좋은 평가가 아니라 검수 과정, 추적 가능한 근거, 오류 예방, 심의 준비 시간 절감이다. 평가 결과를 돈으로 바꿀 수 없도록 영업과 판정 기준을 분리한다.
